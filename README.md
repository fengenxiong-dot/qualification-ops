# 任职资格认证运营台

当前版本覆盖资格标准制定、被评价人在线举证、Excel 批量导入和评审录入阶段。管理员可在系统中新建或从已导入 Excel 复制资格标准；标准定稿存档后，被评价人可登录系统逐项填写工作成果、行为举证与自评，上传或关联附件，保存草稿后正式提交。提交后申请直接复用现有评审配置、逐项评分和结果看板流程。

资格标准按“职族 → 职类 → 子类”管理，每个子类采用一份分级矩阵覆盖多个职级。在资格标准页面建立分类目录后，选择子类并新建标准；旧标准保留原分类文字并列在“待归类”中，定稿存档前需指定子类。子类支持配置一级至七级各自的岗位名称，并支持批量粘贴。

资格标准下设默认折叠的“标准开发”和“标准存档”菜单。开发区支持起草与迭代，每次保存记录操作人、时间、修订说明及完整内容快照，点击“版本留痕”可展开回看。矩阵定稿存档会检查所属子类、每个维度的子维度及各等级描述的完整性；存档版本不可修改或删除，分类和岗位名称也按存档时保存。旧格式标准仍沿用原有条目及权重检查。

从存档发起迭代需填写说明，系统复制为同一标准系列的新版本（V1、V2、V3…），保留来源版本。每个系列同时只允许一个开发版本，可从任意历史存档版本发起；存档版本仍可引用，举证申请记录具体版本及内容快照，后续迭代不改变已有申请。为保留留痕，开发记录也不提供物理删除。旧“已发布”标准不会自动视为已存档，管理员须在开发区确认内容并定稿存档后才能新增引用；已有申请和评分不变。

## 分级矩阵编写

- 层级映射：初做者 1–2 级、专业级 3–4 级、骨干级 5–6 级、专家级 7–9 级、教授级 10–12 级。目前仅开放一级至七级；按层级编写的专家级描述当前仅用于七级申请。
- 默认基本条件、行为标准、专业成果&团队成长贡献按职级编写；知识、技能、能力素质按层级编写。仅填写标准要求，不要求认证方法。
- 管理员通过“维度模板配置”增删、调整维度及编写口径，也可预置子维度。模板变更仅影响后续新建标准。具体标准可增删、重命名和排序子维度；现有角色中由管理员承担标准开发操作。
- 高等级自动继承低等级要求，每格只写新增要求。空白代表待编写，使用“无新增要求”按钮明确表示继承而无新增。存档前所有格子需完成。
- “批量粘贴”支持 Excel、网页表格及 AI 生成的 Markdown 表格；可按等级表头匹配列、按子维度名称匹配或新增行。先预览再应用，空白不覆盖原内容；应用后可撤销，后续手动修改后撤销入口关闭。
- 新建、继续开发和发起迭代统一进入分级矩阵编辑器。旧格式开发版本在新版界面中保留原文对照，确认原内容对应职级并点击“填入对应等级”后即可保存，其余等级留待编写。旧存档始终保持原内容，只读查看。
- 标准存档按子类只显示最新存档版本；通过“历史版本”入口查看该子类的全部存档及版本留痕。隐藏历史卡片不会删除版本或改变已有举证引用。

在线举证只能引用已存档标准，选择申报职级后自动生成包含继承要求的材料填写项，保存对应标准版本和岗位名称快照。参考类维度同样需要填写举证，但不参与数值计分；行为评分和成果加分沿用既有规则。管理员可配置维度的评审类型。系统不自动推定评分权重：矩阵申请进入评分前，管理员需在材料详情中配置行为项权重，合计 100%；产生评审记录后权重不可修改。

批量导入采用逐文件二进制上传，避免将整批文件编码成 Base64 后占用大量浏览器内存。

解析器通过“评估项目/工作模块”表头、“团队成长贡献加分项”和“综合得分”标识动态确定数据区间，兼容行为标准从第 5 行或第 6 行开始的模板。评审目录固定分为行为标准、团队成长贡献、附件和总体评价；行为标准单项满分 5 分，团队成长贡献单项最多加 2 分。

评委总分按 `Σ((行为标准原始分 ÷ 5) × 100 × 权重) + Σ(团队成长贡献原始分)` 实时计算。评分页顶部申报人信息与总分保持悬浮，支持展开折算明细；团队成长贡献采用紧凑卡片，附件默认折叠。

## 管理员配置的在线举证

1. 进入“材料举证 → 举证配置”，点击“配置举证人”，填写工号、姓名、当前职级，选择子类最新存档矩阵和本次认证等级，生成专属举证码。新工号同步建立人员档案，并以当前职级作为初始职级；已有工号自动带出姓名及档案当前职级，本次认证自动归入同一档案。工号忽略首尾空格及字母大小写，保留数字前导零。姓名或当前职级与已有档案不一致时提示核对，不覆盖既有职级历史。任务、档案及认证关联在同一事务内保存。完整举证码仅显示一次，重置会撤销旧码及旧会话。
2. 举证人在 `/evidence` 输入举证码登录，只能访问本任务。姓名、标准版本和等级锁定；页面展示对应等级及继承要求。在每个举证项的文字下方添加文件或链接，同一项支持多份附件，每份附件必须且只能归属一个举证项。文字可保存草稿，多文件上传前会先保存文字；可编辑时可调整附件归属。历史未关联或关联多项的在线附件须指定唯一归属后才能提交或定稿。
3. 支持 PNG/JPEG/GIF/WebP/BMP/TIFF、PDF、Word、Excel、PPT、文本、CSV、RTF、OpenDocument 和 ZIP/7z；不接收可执行文件、HTML、SVG。单文件上限沿用 `CERT_MAX_FILE_MB`（默认 300MB）。文件仅按扩展名和大小检查，尚未集成病毒扫描；附件应来自可信来源。
4. 提交后状态为“待管理员确认”，举证人不可修改。管理员在材料列表详情中发送反馈、退回修改或确认定稿；退回时必须填写意见。举证人点击“刷新反馈与状态”后继续修改和再提交。
5. 定稿后材料锁定。管理员须先完整配置所有普通评分子维度的权重，合计100%，才能配置评委；缺少权重或合计不正确时，点击“分配评委”或在评审配置中选择该人员，会提示先配置子维度权重。后台保存和 Excel 批量导入也执行同一检查。未定稿任务不会进入可分配名单，后台也拒绝分配及评分。系统不会自动分配权重。
6. 评委在每项文字举证下方查看对应附件；图片支持缩略图和大图查看，PDF 提供浏览器预览和下载，Office 及压缩包等格式可下载后查看。预览、下载沿用任务与评委访问权限。历史 Excel 导入的关联关系保留，不自动猜测归属。

配置、提交、退回、反馈、附件变动与定稿记录保存在数据库；提交时保留文字及附件清单快照。举证码与8小时会话仅保存摘要，文件访问按任务或已分配评审入口校验。旧 Excel 导入及原有在线申请不强制套用新确认流程。

当前默认服务只监听 `127.0.0.1`，本机模拟管理员仅用于开发。其他电脑访问需另行配置内网地址和 HTTPS；远程不能通过模拟身份获得管理员权限。不要把当前开发服务直接暴露到公网。

## 人员职级档案

“结果看板”之后新增“人员职级”，用于维护人员初始职级、汇总当前职级、查看历次认证及晋级情况。管理员可搜索姓名、工号或部门，按当前职级筛选，点击人员查看时间线、评委评分和维护留痕。

- 新配置的举证人按必填工号自动建档及关联认证，后续再次认证沿用同一档案，最初的初始职级不变。当前职级按已确认并生效的结果展示，不直接使用本次申报等级。未定级人员可明确填写“未定级”。
- 已有、尚无工号的历史认证材料保留在“历史待关联认证材料”，管理员核对工号后关联到实际人员。姓名相同不会自动合并。初始职级来自首次配置的当前职级或历史建档录入，不从申报职级推定。
- 一份系统认证材料只能关联一人，同一人员可关联多次认证。系统评审全部完成且评委权重合计100%后，管理员确认通过或未通过，填写结论日期；通过时还需填写生效职级、生效日期，并明确是否晋级。
- 未通过认证保留原职级，未来日期的晋级在生效前不计入当前职级和已生效晋级次数。对于一级至七级、T/P/M等可比较编号，晋级后等级须高于此前等级；不同职级体系由管理员核对。
- 可补录往年认证，填写申报职级、职类、结论、日期及历史来源；分数可选填。确认时保存评审数据快照，后续评分变化不改写历史。修订正式结论需填写原因并保留旧快照；已有确认记录后，初始职级和初始日期锁定。
- 支持导出全部、筛选结果及个人 Excel 档案，包含人员清单、认证与职级变迁、评委评分明细、待关联材料及统计口径。待关联材料不计入具体人员的认证和晋级次数。

## 启动服务

首次运行先安装依赖：

```powershell
python -m pip install -r requirements.txt
```

然后启动：

```powershell
python server.py
```

浏览器访问 `http://127.0.0.1:8787`。

如需指定端口：

```powershell
$env:CERT_PORT=9000
python server.py
```

## 数据目录

- SQLite 数据库：`data/certification.db`
- 原始 Excel 与附件截图：`data/submissions/`
- 待确认的批次：`data/staging/`

原始 Excel 始终保留，用于追溯。当前解析规则针对 `2-1职级认证申请及成果评估表` 与 `2-2员工举证附件材料区`。
